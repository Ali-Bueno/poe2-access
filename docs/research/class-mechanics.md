# Class-specific mechanics: what each class must track, where the game keeps it, what the mod says (0.5.x, 2026-11-08)

Offline research on the game files (bundle index of build 26476662, read with `tools/Poe2UiExtract`), the host's
memory model and the web (poe2db, patch notes); the test character is a level-22 Mercenary in Act 2, so everything
below the Mercenary's own content is **ready but unheard**. Live protocols at the end. Companion documents:
[skill cooldowns](skill-cooldowns.md), [parry and stun bar](parry-and-stun-bar.md), [game data sources](game-data-sources.md).

Confidence: **PROVEN** = read in the game's tables or seen live; **LIKELY** = tables plus a documented game rule, not
seen live; **UNSURE** = web or inference only.

## 2. The game's own words for the mechanics (PROVEN: KeywordPopups.datc64, Id +0x0, title +0x8, text +0x10)

| Keyword | Rule the text states |
|---|---|
| Rage (41) | +1% attack damage per Rage; **30 maximum by default**, −1 every 0.2 s, loss paused 4 s after gaining or taking damage; one hit per 0.5 s can grant Rage |
| Charges (151) | Endurance, Frenzy, Power; **3 of each by default**, last 15 s, refreshed by another of the same type |
| Combo (253) | a counter **on some skills**; built by Strikes with the weapon the skill is bound to; falls off after a short time; **lost on weapon swap** |
| Glory (478) | spent by certain skills; generated by actions against enemies = monster Power; **each skill gains and loses it separately**, once per 0.5 s per monster |
| Valour (269) | fuels Banner skills: 1 per attack kill, +1/s per unique in presence; 50 per Banner by default |
| Banner (403) | generates Glory while activated; at full Glory the banner is placed; one placed at a time |
| Spirit (127) | reserve for persistent skills, managed in the Skills Panel; differs per weapon set |
| Minion (132), Command (299), Companion (412), TemporaryMinion (598) | persistent minions reserve Spirit; some minions take Command skills; one Companion of a type |
| Totem (79) | allied constructs, limit shared between totem types |
| Warcry (133) | counts enemy Power in the area and Empowers the next melee attacks |
| Ammunition (195), Grenade (316) | an Ammunition skill loads the crossbow (does not fire); grenades have a fuse, cooldowns, need a crossbow |
| Surge (401), ElementalInfusion (573) | 6 of each Surge per weapon, 15 s; Infusions from Remnants, 20 s, 3 of each |
| Remnant (396) | objects on the ground that player skills create; walked over to collect |
| Mark (237), Curse (134) | one Mark per enemy; one Curse per target by default |
| Parry (446), Block (70), HeavyStun / HeavyStunPlayer (57/58) | players build stun only while raising a shield, parrying with a buckler or riding |
| Shapeshift (43) | non-human forms; an incompatible skill shifts back |
| Tailwind (261), Jade (262), UnboundFury (294), PurpleFlamesOfChayula (337), RunicBinding (312), UnboundPotential (313), Volatility (406), Archon (591), Energy (145), Concentration (263), Honour (276) | ascendancy stacks: Tailwind 10 (all lost when hit), Jade 10, Purple Flames 10, Runic Bindings 10 / 10 s, Unbound Potential 10 (−1 per 5 s), Archon 10 s then 20 s recovery, Energy per Meta skill |

## 3. Where the game keeps each resource (what the mod can read)

### 3.1 Player buffs — stacks as the count (PROVEN for charges and the Combo, LIKELY for the rest)

`Buffs` component → `StatusEffectStruct` (`host/GameOffsets/Objects/Components/Buffs.cs`): definition pointer,
`TotalTime`/`TimeLeft` (s), `Charges` (stacks, +0x40). GameHelper keys the dictionary by BuffDefinitions Id plus an
instance suffix (`power_charge_79`; `BuffIds.Base` strips it). `BuffDefinitions.datc64` (3218 rows): Id +0x0,
description +0x8, **display Name +0x12**, **type byte +0x67**. Types seen: 1 boosts/auras, 2 ailments and boss debuffs,
3 charges, 4 flask effects, 5 curses, 6 skill stages (Blade Flurry, Volcano, Gemling "Intelligence Motes"), 7/9 shrines,
13 heralds, 14 marks (on the enemy), 17 charms, 18 misc player states (Unbound Fury, Demonflame, Overheated, Grace Period,
Called Shots). Hidden rows carry "[Not Displayed]"/"[DNT…]" names. No column holds a stack maximum: maxima are Stats (§3.2)
or the KeywordPopups default (§2).

Resource buffs (id → game name): `power_charge`/`frenzy_charge`/`endurance_charge`/`spirit_charge` (3), `arcane_surge`,
`fire/cold/lightning_infusion`, `verisium_infusion`, `instilling_fire/cold/lightning/chaos` ("… Surge"), `druidic_prowess`
(max 3), `jade_stacks` ("Jade"), `tailwind`, `ailment_bearer_activation_buff` ("Unbound Fury") → `ailment_bearer_buff`
("Unbound"), `archon_fire/cold/lightning/elemental/undeath/nature`, `archon_of_chayula`, `demon_form_buff` ("Demonflame"),
`infernal_flame` (no name: the stat is the source), `owl_feather` ("Primal Owl Feather"), `vivid_wisp_buff` ("Vivid Wisp"),
`wild_beast_storage` ("Savage Fury") → `wild_beast_frenzy`, `runic_binding` → `runic_fury` ("Unbound Potential"),
`runic_tempering` ("Runic Plates"), `mantra_of_destruction`, `meditate_energy_generation` ("Meditate"), `gemling_barrier_*`
("… Motes"), `support_static_charge` ("Voltaic Charge"), `heat` + `overheated` (crossbow), `emergency_reload_visual`,
`ascendancy_deadeye_marks_ready/cooldown` ("Called Shots"), `beast_companion`, `wolf_pack`, `raging_spirits_buff`,
`*_invocation_count` / `cast_on_block_count` (Energy of Meta skills, no name), `tempest_bell_combo_tracker` (hidden; stacks
= Combo, seen live), `tempest_bell_active` ("Tempest Bell").

### 3.2 Player Stats — pools and limits (PROVEN pairing; values LIKELY until heard)

`Stats` component dictionaries (`StatsChangedByBuffAndActions` first, `StatsChangedByItems`), keys = `Stats.datc64` row + 1
(`GameIds`). The table pairs resources by name alone, so `tools/Poe2UiExtract class-mechanics` derives them without a list
(`ClassMechanics.Resources/Limits`, 79 + 22 pairs in this build):

* `current_rage` / `maximum_rage` / `virtual_maximum_rage` (ChargeWatch, live) · `current_power/frenzy/endurance/spirit_charges`
  with `max_` and `virtual_maximum_` · `current_infernal_flame` / `maximum_infernal_flame` (Infernalist) ·
  `current_demon_form_stacks` / `max_demon_form_stacks` · `current_number_of_crossbow_heat_stacks` / `maximum_…` (Rapid Shot)
  · `current_fury_charges` / `virtual_maximum_fury_charges` · `current_fire/cold/lightning_infusion_stacks`,
  `current_instilling_chaos_stacks`, `current_verisium_infusion_stacks` · `current_focus_lost` / `maximum_focus`.
* Limits: `number_of_active_totems` / `number_of_totems_allowed`, likewise skeletons, zombies, raging_spirits, spectres,
  wolves, beast_minions, infernal_familiars, tempest_bells, generic_limited_minions, replicate_minions, the six offerings.
* Maxima without a current (the buff is the count): `max_jade_stacks`, `max_adaptations`, `maximum_darkness_+%`,
  `maximum_number_of_purple_flames`, `number_of_marks_allowed_per_type`, `number_of_additional_curses_allowed`,
  `number_of_crossbow_bolts` / `base_number_of_crossbow_bolts` (clip size).

### 3.3 Per-skill counters — not in the player (PROVEN in the tables, memory UNSURE)

Combo, Glory and the crossbow clip are skill stats, not player stats: `skill_current_number_of_combo_stacks`,
`active_skill_required_number_of_combo_stacks`, `active_skill_requires_X_glory`, `virtual_amount_of_glory_required`,
`skill_is_crossbow_ammo_skill`, `crossbow_ammo_has_no_ammo`, `crossbow_ammo_skill_has_passive_reloading`,
`number_of_crossbow_bolts`. They live in the skill's own stat block (GameHelper's `ActiveSkillDetails`, ~0x100 bytes per
listed skill, `StatsPtr` noted at +0xB0 but unverified). The dev command `skills` (`SkillDetailsDump`) prints every non-zero
int32 of each listed skill with its name, granted id and skill types, so the bolt counter is the field that drops by one per
shot (§7.1, doable now with the Mercenary).

### 3.4 Skill types — what the class uses (PROVEN)

`ActiveSkills.datc64` row +0x40 is a key list into `ActiveSkillType.datc64` (290 rows: Minion, CreatesMinion, CommandsMinions,
SummonsTotem, SummonsAttackTotem, Warcry, Banner, Stance, Mark, Hex, CrossbowSkill, CrossbowAmmoSkill, Grenade, Shapeshift,
Bear, Wolf, ComboStacking, GeneratesCharges, ConsumesCharges, SkillConsumesPowerChargesOnUse, Offering, Invocation, Persistent,
Sustained, Guard, Retaliation, PerfectTiming, Meta…). `GrantedEffects` +0x4F keys the ActiveSkill. The catalog maps each
granted effect the Actor can list ("WarBannerPlayer" → Attack, Banner; "ExplosiveGrenadePlayer" → Grenade;
"ArmourPiercingBoltsAmmoPlayer" → CrossbowAmmoSkill; "ParryPlayer" → RequiresBuckler, Channel, ActiveBlock) — the
extractor verifies the columns on `war_banner`/Banner and `explosive_grenade`/Grenade and scans for them if they moved.

### 3.5 Placed things (PROVEN paths, entity reading LIKELY)

Banners placed: `metadata/effects/spells/banner/warbannerground.ot`, `dreadbannerground.ot`, `armourevasionbannerground.ot`
(Defiance). Totems: `Metadata/Monsters/Totems/…` (friendly monsters without NPC: `MinionReport` counts them as minions —
totems are not minions, §6). Tempest Bell and Frozen Locus crystal: `DeployedObjects` (live). Remnants (Life, Mana, Infusion,
Runic Ward): no `.ot` named remnant outside Expedition; find their paths live with the entity dump when a Blood Mage or
Stormweaver is played.

### 3.6 HUD (PROVEN names, reading not needed)

`metadata/ui/ingamestate/hud/hud*.ui`: `RageBar` (ClientStrings `OrbRageValue` "Rage"), `SpiritBarFrame`, `MinionDisplay`
(`minion_display` under `top_icons_layout`), `MagmaManaOrb` (the Infernalist's flame orb). Skill costs show as
`SkillPopupCostValueRage` "{0} Rage", `SkillPopupCostValueSpirit`; the Skills panel's spirit/capacity is already read. Minion
command skills switch mode in their context menu (`MinionSkillAutoMode`/`ManualMode`: "Select to enable auto mode"), read
generically as context-menu rows. Everything the HUD shows for these resources is in memory (§3.1–3.2), so the mod reads
memory, not widgets: no widget semantics were needed for this domain.

## 5. What the mod does now (code map)

* **Live before this work:** `ChargeWatch` + `PlayerCharges` (charges, infusions, surges, Druidic Prowess, Arcane Surge,
  Tempest Bell Combo, Rage edges), `SkillCooldownWatch` (skills ready), `ShieldWatch` + `ShieldStance`/`StunMeter`,
  `ParryTiming`, `MinionReport` + `MinionGroups`, `InventoryWatch.TickWeaponSet` (weapon set 1/2), `DeployedWatch` (bell,
  crystal), `StatusWatch`/`StatusAilments` (Overheated, ailments), `CullWatch`.
* **New (2026-11-08, code):** `tools/Poe2UiExtract class-mechanics` → `catalog/class-mechanics.json` (`ClassMechanics` pure
  pairing + `ClassMechanicExtractor`; launcher step "class mechanics" v1); plugin `ClassMechanicCatalog` (stats, limits,
  1098 buff names in 10 languages, 7465 typed granted effects), `ResourceTracker` (pure diff-gate: counted resources settle
  400 ms, pools tell full/empty, a 2 s baseline grace after a reset), `ResourceWatch` in `PlayerAlerts` beside `ChargeWatch`
  (stats not covered by the charges, limits as edges "Tótems al máximo, 3" / "sin Tótems", every named non-harmful buff's
  stacks "Jade: 7", a one-stack buff "Unbound" / "Unbound se acabó" only when it lasts ≥ 8 s or is untimed, a buff a stat
  already counts skipped, ends said only after a said beginning), `Announcements.ClassMechanics` (known names in EN/ES; any
  other is logged, not spoken, since 2026-11-10), vitals readout lists what is held, `SkillDetailsDump` (dev `skills`). Switch and level: the
  charges' (`ChargeSpeech`, "Voz: cargas"); no sounds yet.

## 7. Live protocols

### 7.1 Crossbow clip (Mercenary, now)
1. Stand still in town with a bolt skill bound; run dev `skills` (debug/command.txt) → the log lists each skill with
   `+0xNN=value` fields. Fire two bolts (not a full clip), run `skills` again. The ammo skill's field that fell by 2 is the
   clip; `number_of_crossbow_bolts` in the Character panel's Skills popup gives the clip size to compare.
2. Reload (fire until empty or press reload): the field returns to the maximum; `have_reloaded_recently` appears in
   "Player buff seen". Record offset and skill in `GameLayout.SkillSlot` with provenance.
3. Rapid Shot: expect the log "Resource stat:number_of_crossbow_heat_stacks: Count …" and the speech "Calor 3 de 5"
   after 400 ms of quiet; `Overheated` stays `StatusWatch`'s. The buff `heat` must **not** be said twice (dedupe by name).

### 7.2 Charges and resources (Mercenary, now)
Gain Power charges (the game's electric sound, "2 cargas de poder" — unchanged). Vitals (L3 double tap) must list the
resources held after the charges. The log must show "Class mechanics: 79 resources, 22 limits, 1098 buffs, N skills".
Entering an area must say nothing of what is already held (baseline + 2 s grace); the Grace Period buff ends silently.

### 7.3 Warrior / Warbringer (later)
Allocate Jade Heritage: Jade climbs one per second → the first "Jade: 2" after the settle, then every settled count, "Jade se
acabó" when lost. Place a totem: "Tótems al máximo, 1" only when the limit fills; "sin Tótems" when it dies. A Banner at full
Glory placed: the banner entity should appear in the entity dump (path §3.5).

### 7.4 Infernalist / Deadeye / Invoker / Druid (later)
Infernal Flame: "Llama infernal al máximo, N" and "sin Llama infernal" only (pool mode); Demonflame stacks counted.
Tailwind: counts up to 10, "Tailwind se acabó" when hit. Unbound Fury counted, "Unbound" when consumed, "Unbound se acabó".
Druidic Prowess (ChargeWatch kind) unchanged; Savage Fury / Unbound Potential counted; shapeshift: watch "Set de armas"
speech and the log for `CurrentWeaponIndex` values beyond 1.
