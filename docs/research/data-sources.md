# Where what the mod says comes from (2026-11-08)

The mod never looks at pixels: everything is read from the game's memory or its files. What could still depend on the screen
was geometry (where things are drawn, the window's size) and what the game itself draws differently at some window sizes.
This page lists every source by kind, after an audit of every service and the window-size sweeps of 2026-11-07/08.

## Game memory state (exact, no screen)

| What | Where |
|---|---|
| Player level, experience, life, mana, energy shield, spirit | `Player`, `Life` components; `catalog/experience.json` |
| Area and monster level | `AreaInstance.CurrentAreaLevel`, WorldAreas rows |
| Statuses and ailments, charges, Combo, Rage | `Buffs` component (buff ids, checked against every BuffDefinitions id), `Stats` |
| Skill cooldowns, uses | the Actor's cooldown vector (`GameLayout.ActorComponent`, `SkillCooldownWatch`) |
| Culling Strike | enemy `Life` and rarity; thresholds 35/20/10/5 % raised by the player's `culling_strike_threshold_+%` stats |
| Character sheet numbers | the player's `Stats` (`SheetStats`, `PlayerStats`), named by the tooltip's English markup keys |
| Enemies, bosses, attacks, stun, dodge timing | `Actor` animations, `Life`, `ObjectMagicProperties`, Render names; hit times from game files |
| Walls, radar, explored map | the terrain's walkable grid |
| Trial traps | hazard entities' `StateMachine` states, paths from game files |
| World map pins | MapPins and WorldAreas rows the map keeps (`MapPinNarrator`, endgame-ui.md §6) |
| Camera: what is seen, pan, directions | the camera's matrix, its own aspect divided out (camera-view.md) |
| Passive tree places | the tree canvas's laid-out places (passive-tree.md, stick movement) |

## Game files (catalogs regenerated by the launcher after a patch)

Item and drop sounds, area names, dat columns, experience, hit times, hazards, culling skills, game ids (animations, stats),
places, the UI catalog, world titles (localized labels such as "Nivel de monstruos: {0}"), map hints.

## Text the game shows, read from its UI in memory

Menus, panels, tooltips, the HUD's quest tracker, the Trial's honour line and counters, the death screen's fallback, chat,
trade offers, the league encounter tracker. This is the game's own text in the client's language, not pixels; layout only
orders it, in the game's own units (`UiSemantics.LayoutRect`), the same at any window size, UI scale or zoom.

## Geometry that remains, and why it is safe

- `ScreenWatcher`'s off-screen test (a control parked outside the root, like the login's "Deal of the Day"): an intersection
  with the root's own rect, no constant.
- Sibling places in the game's unscaled units: class icons in a row, map markers, rows merged on a line (`SameLineTolerance`).
- The measured camera (`CameraView` constants) only when the matrix cannot be read.

## What the game itself changes with the window

- A 5:4 window hides some Fontin Smallcaps captions (flag 0x5026F1 instead of 0x502EF1): the sheet's captions (named from
  the stats instead), the inventory header's area name, the passive tree header's points and attributes, two cosmetics tabs.
  16:9, 16:10 and 21:9 hide none. Hidden for every player at that size; not read, since a hidden element cannot be told from
  one hidden for real (a closed tab) by its flags.
- At 5:4 a world map pin's popup arrives in two parts; the pins are told from their data when it was not heard.

## Not measured

- The monitor off: this PC enters modern standby with it (camera-view.md); nothing the mod hears depends on the window now.
- Windows display scaling at 125-150 %: no decision uses pixels any more, so it should not matter; untried.
- Honour now and the Trial's keys and water exist only as HUD text: no stat holds the current honour (only modifiers and
  `total_sanctum_honour`), and no Trial run was made to look for them in server data.
