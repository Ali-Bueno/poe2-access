### Lessons and pitfalls (navigation)
1. Only real collision changes sound; walking speed or queue length must never change the verdict (user rule) - docs/radar-redesign.md:11-13, 79-91.
2. Confirm changes by travelled distance (one cell) or two polls when stationary, not by time or forecast - docs/radar-redesign.md:44-50; docs/radar-running-timing.md:63-75 (forecast approach reverted).
3. Backing away from a warned wall must not read as a new opening; anchor wall memory in world coordinates - docs/radar-redesign.md:52-77.
4. A cue you cannot act on is worse than none (floor vs "leads somewhere") - docs/radar-readings.md:6-10.
5. Monsters and other actors must never create wall cues: strip actor/NO_PATH stamps, unknown/blank is never wall, never opening - docs/collision-semantics.md:63-78 (orphan NO_PATH produced a false wall).
6. Do not erase small obstacles as clutter when the character stops at them; the radar then called open what blocked - docs/radar-readings.md:85-96.
7. Lateral slack in the passage scan hid walls until contact (76% of wall cues at depth 0); measure the straight route - docs/radar-redesign.md:173-195.
8. Try audio changes with the user's ears: 8 rays, speed-scaled thresholds, new cue design and diagonal default were all reverted after listening - docs/radar-redesign.md:154-168; docs/radar-readings.md:25-28.
9. Naming something behind a wall makes the player walk into the wall; gate automatic announcements by line of sight with positive evidence only - docs/npc-proximity.md:29-33; docs/target-sight.md:1-34.
10. Game auto-target flickers between pack members; repeat guards are required (crosshair beeped 2077 times, 26 per 10 s; plate names traded every 160 ms) - docs/crosshair.md:52-56; docs/attack-reach.md:103-127.
11. One cue stream per class so a nearest boss cannot starve others; give each class a distinct timbre/rhythm (enemy whoosh sounded like the radar breath) - docs/entity-cues.md:45-61.
12. Short clicks and quiet recordings are inaudible under gameplay: peak-normalise on load, measure loudness (LUFS) and trim per sound - docs/ground-items.md:74-81, 141-147, 163-171.
13. A raised volume setting must not lower others: apply per-family gain on the voice past the headroom - docs/ground-items.md:300-307; docs/decisions.md:114-115.
14. Speech from announcements in the first 2.5 s of a level is cut by the area banner; hold it - docs/exploration.md:227-233.
15. Synchronous log flush on the UI thread caused 700-1000 ms stalls; log through a bounded async queue - docs/navigation-latency.md:10-22.

### Lessons and pitfalls (menus)

1. Unknown is not empty: never say "empty" because a tooltip/read failed; read the slot data and treat a failure as unknown (`docs/native-tooltips.md:167-169,225-228`; `docs/inventory-npc-followup.md:75-78`).
2. A slot/label read can miss while a panel rebuilds: cache the last good value per element id so the announcement never goes silent (`docs/character-panel.md:46-59`).
3. A tooltip can be stale: attach it only if the focus identity/selection captured with it matches the current one (`docs/skill-actions.md:10-13`; `docs/native-tooltips.md:33-35`).
4. Check that tooltip line order equals screen order; D2R stored it bottom-up and every item read backwards (`docs/native-tooltips.md:340-348`).
5. Strip markup/font-command AND its index character, or every line starts with a stray "0"/"5" (`docs/native-tooltips.md:354-369`).
6. Glyph-only lines stay silent, unknown glyphs are dropped, known ones named ("Press to continue" bug) (`docs/controller-glyphs.md:3-6,47-49`).
7. A panel that is open but draws nothing must never own focus or block world readers (emote wheel stayed "focused" until another panel opened) (`docs/native-ui.md:188-197`).
8. HUD panels open all game long must not be in the "menu open" gate, or radar/keys stay off for the whole session (`docs/keyboard-play.md:130,203`).
9. Last-interrupt-wins loses critical news; a beginning effect heard "no longer chilled" but never "chilled": use hold/lead windows and one combined utterance, critical first (`docs/status-effects.md:43-45`; `docs/vitals.md:73-76`).
10. Auto-target hops make name/beep cues explode (2077 beeps; plate traded names every 160 ms): add a repeat window and speak on first uninterrupted display only (`docs/crosshair.md:48-56`; `docs/attack-reach.md:105-123`).
11. A spoken warning lags behind fast combat; use a sound (heartbeat) for the critical state, speech for detail (`docs/decisions.md:371`; `docs/vitals.md:141-146`).
12. Availability flags can lie: decide "has this quest" by content (pane heading matches), not by a byte/enabled bit (`docs/quests.md:63-92`).
13. A control that vanishes on the last use (the "+" at 0 points) takes focus and speech with it: remember its last value and speak the result (`docs/progression.md:36-46`).
14. Modal closing is not confirmation: say the outcome only after seeing the command/result (`docs/delete-character-modal.md:137-144`); legends may be empty, so fall back to the default binding but log it (`:119-126`).
15. Any synthetic input flips the game's input mode and rebuilds panels (a mouse click made the game reload every panel as mouse layout); keep the mod read-only (`docs/multiplayer.md:240-245`; `docs/controller-mode.md:20-22`).

### Lessons and pitfalls (settings)

- First live tutorial test: the NPC announcer, the area banner (interrupting) and new-exit news cut the welcome; gate non-urgent speech on "no speech started for 1.5 s" and queue behind news (docs/tutorial.md:102-106).
- A message gated on "game text owns speech" never spoke inside menus; menu-scoped messages wait only for a pause (docs/tutorial.md:228-231).
- A tutorial step that waits for an event that may never occur (gold drop) silently stalls all later steps; end steps on a state that always happens (a kill) (docs/tutorial.md:94-98,161-165).
- Key per-character records by name AND creation time; a delete+recreate keeps the old record and Windows tunnelling keeps old creation time for 15 s (docs/tutorial.md:77-87).
- Teach a sound with its name and meaning FIRST and the sound right after; sounds playing over the lesson ("people have to hear well what each sound means") must be quieted (docs/tutorial.md:107-121).
- A button the game already owns gets double meaning (beacon on L3 toggled run): check the game's binding before assigning a gesture (docs/decisions.md:643-645).
- Do not speak what the game does by itself ("Walking" when the game forces walk against a wall); speak only on the player's own press (docs/decisions.md:597-598).
- A spoken warning that lags is worse than a sound: low life became a heartbeat (docs/decisions.md:370-373).
- Arrival news lost to a hover name: hold 1.5 s for arrivals; an eclipse news lost under the banner: wait for a pause (docs/speech-priority.md:26-29,51-56).
- Unknown glyphs vanish from game text ("Press to continue"): decode every glyph range, drop only the unnameable (docs/controller-glyphs.md:3-7).
- Do not invent names for places the game does not name (no "tavern"); build names from game data (docs/decisions.md:718-727,694-700).
- A HUD widget (aura) read by a fallback focus reader spoke "Paladin Aura" at loading: skip HUD-only panels in generic readers (docs/decisions.md:50-55).
- Check the game's text locale before trusting a spoken-output log; an English run is not a valid check (docs/testing.md:40-42).
- Add a field to a shared strings table and a stale object shifted every string read, crashing the game: rebuild all consumers and verify dependency tracking (STATUS.md:70-74).
- Re-check cue verdicts on an independent decode of the logged RLE snapshot before concluding a cue is wrong (docs/testing.md:44-51).
